# D02：个人信息保存与明确更新，还需补齐什么

核对基线：主线 `5161414`。依据 [第二版开发任务 D02](/home/herman/Documents/Repo/Projects/DSHPlugins/个人Feed/第二版开发任务.md) 和 [D00 共享交接约定](d00-handoff.md)。本文展开当前缺口与完成依据，不修改实现或勾选任务完成。

**D02 的终点：用户明确改了哪部分，系统就准确改哪部分；随后读到的是当前有效信息，重启后仍然成立。**

现有基础可以继续用：两类事实已分开标记并落盘，同一句关注可以切换 include/exclude，原子写入和并发冲突检查已经存在。缺少的是完整的局部修改表达、提交行为和确定信息读取。

## 1. 让更新明确指向旧事实

当前模型只交出一组 `facts`，应用按“类别＋陈述原句”合并。只要纠正后的说法不同，系统就新增一条，原认识仍然保留。

例如旧认识 A 是“自动剪辑适合所有视频”，用户改为“只适合简单口播，复杂叙事不能直接套用”。更新后应只留下明确的新范围；原来的泛化结论不能继续生效，另一条无关认识 B 和长期关注必须保持原样。

D00 已确定使用 `additions` 和 `replacements`；每次替换包含读取到的完整 `target` 原事实和替换列表。D02 还需把这套表达接进明确更新的模型输出、严格解析与提交逻辑。不能只改提示词，仍让应用执行旧的按句合并。

## 2. 实现四种操作，尤其是撤回和局部拆分

| 操作 | 应有行为 | 当前差距 |
| --- | --- | --- |
| 新增 | 增加明确事实，无关事实不变；相同事实重复输入不重复增加 | 已有基本合并，需要按新约定保留和验证 |
| 保留 | 未列为修改目标的事实不动 | 已有基础，需要在替换和撤回时继续保证 |
| 撤回 | 指向旧事实，替换列表为空，使旧事实不再生效 | 当前没有删除旧认识的操作；模型不再返回它也不会删除 |
| 更新或缩小范围 | 替换指定原事实，必要时拆成多条明确或待澄清事实 | 当前不同说法会共存，无法可靠替换 |

“不再关注某主题”已有 `exclude` 表达，不能据此认为已有认识也支持撤回。把认识标为 `uncertain` 表示仍有疑问，也不等于用户明确撤回。

同一个目标在一批修改中只出现一次；目标必须匹配实际读到的完整事实。无法确定修改对象时，不猜测删除范围，将未明确部分交给 D05。提交前目标已被其他更新改变时，沿用已有冲突处理，不覆盖较新的结果。

## 3. 分开维护信息和用于筛选的确定信息

存储需要保留待澄清事实，但筛选读取必须排除 `uncertain`。当前代码把保存的全部事实交给判断，且只要有任意一条已有认识就可能认为信息足够。

部分明确的表达应能分开保存。例如“简单口播仍适用；复杂叙事我还拿不准”，应保留前者为确定认识，后者为待澄清；不能把整条都当成已知，也不能丢掉已经明确的部分。

D02 要提供可信的确定信息读取结果，供 D04、D05 使用。“我是这个领域的新手”是明确的知识边界，可以保存为已有认识；“尚未提供认识”则不是同一状态。排除疑问后是否足够支持具体请求，需要与 D04、D05 按 D00 联调，不能用事实数量代替判断。

## 4. 让变更立即可见，并返回准确的变更数量

明确更新成功返回前应已完成保存；紧接着读取、新建应用或新进程重读，都应得到相同结果。替换和撤回也必须具备现有新增的持久化保证。

`appliedCount` 目前按事实总数的增量计算，因此改了同一句关注仍可能返回 0。按 D00，应改为实际变更项数：新增一条计一项，替换或撤回一个目标计一项，重复新增和等值替换计零项。一条旧认识拆成两条仍是一次目标替换。

现有原子写入、读取校验和冲突检查应复用；需要补足新操作的保护用例，不必另建存储或版本系统。

## 5. 保持用户表达的边界

独立的明确更新只更新信息，不要求用户先补齐另一类信息，也不自行启动 X 获取或 Feed 筛选。同条消息明确更新并请求 Feed 时，D02 提交新状态，D04 使用这份更新后的信息。

仅收到、点击或收藏内容，不增加已有认识；原因不明的负面反馈也不改变关注或认识。D02 负责接收明确变更和保存相应状态；追问什么、如何理解仍含糊的回答归 D05，原请求的等待和自动续做归 D06。

## 6. 需要留下的完成证据

模型解释和 X 材料可以使用受控替身，但事实提交、重读和隔离必须运行真实应用逻辑。

| 用例 | 必须核对的结果 |
| --- | --- |
| 两类信息新增与重复新增 | 分类正确，重复项不增加，准确计数，新进程能重读 |
| 明确纠正 A，保留 B | 旧 A 不再生效，新 A 可见，B 和关注完全保留 |
| 明确撤回 A | 重读和新进程读取均无 A，其他事实不变 |
| 一条认识部分确定、部分存疑 | 存储保留两部分，有效读取只含确定部分 |
| 明确认识变成疑问 | 原确定认识停止生效，疑问仍可供后续澄清使用 |
| 新手陈述 | 明确的新手知识边界可保存，不被当成未提供信息 |
| 更新当次可见 | 同次请求的候选判断实际收到新事实；此项与 D04 联调 |
| 目标已变化或修改格式无效 | 不误改无关事实，不覆盖新状态，不留下半批变更 |
| 普通更新与收藏 | 无原 Feed 时不调用观察器或判断；收藏不新增认识 |
| 保存失败与重启 | 保存失败不报告成功；成功提交的替换、撤回和疑问状态可跨进程读取 |

此前在同一基线运行的 15 项现有应用／模型测试通过；临时样例验证了两类信息跨进程重读、同句更新、无关信息保留和收藏不增加认识，也复现了改写后新旧认识并存、不能通过省略撤回、疑问进入筛选及变更计数不准确。临时调查样例不是已入库的回归测试，新行为仍需按项目规则先写失败测试。

**建议实施顺序：** 先接入局部变更表达并实现新增／替换／撤回，再提供确定信息读取，随后补齐计数、冲突与持久化用例，最后与 D04、D05 核对交接。主要涉及 `src/application.ts`、`src/openai-compatible-model.ts` 和相关测试；D00 已给出核心规则，目前没有必要为 D02 再增加一轮产品选择。
