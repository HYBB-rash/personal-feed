# Personal Feed 修复方案

**后台用已有信息安静地监控；你主动聊天时，再把你的兴趣和认识聊清楚。**

2026-09-07 讨论稿。这里只说明打算怎么改，程序尚未修改。

## 你实际会怎样使用

### 你不在场：系统定时找内容

定时任务启动 Personal Feed，按照已经了解的兴趣和认识，看看现在有没有值得推荐给你的内容；有合适的内容，就发到 Telegram。

这个过程不向你追问需求，也不停下来等你回答。

**我的建议：**如果现有信息确实不足以判断，就结束这一轮，并在系统内部留下原因。不能凭空猜你的认识，也不把“请补充资料”当成监控结果推给你。这一点是方案建议，不是已经验证的行为。

### 你在场：边聊天，边让系统更了解你

例如，你看完一条内容后说：“我对 AI 视频感兴趣，但还没有实际做过。”

系统按你明确表达的意思更新了解；如果还有需要问清的地方，就在 Telegram 里给出问题，让你填写或选择答案。你可以修改后提交，也可以取消；提交的答案由程序直接交给 Personal Feed 处理。

以后定时找内容时，就用更新后的认识判断。单纯补充个人情况不会自动要求系统再找一条内容；如果你当时已经请求了推荐，补充完才接着完成那次请求。

## 这次修复要解决什么

之前的问题是：你回答了，信息也保存了，但系统没接上“这个回答属于刚才那件事”，最后只说一句“已记录”就停了。

这次要让固定程序负责接住答案、对应问题、继续处理，并明确告诉你结果：是已经更新、还需要补充，还是这次没处理成功。取消或中断后，也要说明是否还能继续，不能让你猜。

## 分别需要改哪些地方

| 部分 | 要承担的责任 |
| --- | --- |
| Personal Feed | 保存和理解你的兴趣、认识，判断内容是否值得推荐；后台运行时不追问，主动交流时才允许问。它继续是独立服务，可以被不同 Agent 调用。 |
| DeepSeek Harness | 发起任务，把 Personal Feed 的问题交到正确的聊天中，再把你提交的答案送回去。 |
| Telegram 接入程序 | 显示问题、接收填写和按钮操作；等待回答期间继续收消息，避免问了以后反而收不到你的回答。 |

“这次能不能提问”由启动任务的程序明确指定，不靠 Agent 猜你是否在线。

**从本地版本的代码看，后两部分还没有接通这套问答流程。** 因此只修改 Personal Feed 不够；这些发现还没有在实际 Telegram 中验证，详细依据放在[技术附件](/home/herman/Projects/personal-feed/docs/a02-harness-telegram-elicitation-2026-09-07-technical.md)。

## Telegram 里的表单先做到什么程度

建议先使用 Telegram 已有的消息、回复输入框和按钮，做出能填写、检查、提交、取消的问题。这样仍在你熟悉的聊天界面里操作；Telegram 官方已有这些[基础交互能力](https://core.telegram.org/bots/api#forcereply)。

如果实际使用发现，一次修改多个项目很麻烦，再增加 Telegram 内打开的表单页面。它能把多个输入项放在一起，但需要额外开发页面和提交功能；Telegram 支持这种[内嵌页面](https://core.telegram.org/bots/webapps)，目前看不必另做一款 Telegram 客户端。

先后顺序是建议，是否好用要拿手机实际试，不能只凭方案判断。

## 建议分三步做

1. **先验证“问得到，也收得到”。** 在不影响现用系统的测试环境里，跑通一个问题、一次填写、一次更新；同时确认后台任务根本不会提问。重复点提交、取消、回复旧问题，也不能造成重复更新或答错问题。
2. **再验证你的两种真实场景。** 你主动聊天补充认识后，下一轮监控确实用上它；你不在场时，监控照常完成，不等你，也不把旧任务重新塞回聊天。
3. **最后打磨填写体验。** 在手机上试消息和按钮是否顺手，再决定是否需要完整的内嵌表单。

## 哪些已经确定，哪些还没有

已经确定的是：服务保持独立；后台监控不问人；主动交流可以等表单回答；更新后的认识用于后续监控。

还没有验证的是：Harness 和 Telegram 能否可靠完成这一整段问答，以及最简单的填写方式是否足够好用。这些需要先做小范围验证，再估完整工作量。

当前不增加“系统重启以后还要找回旧问答”的要求；已经保存的个人信息继续保留。下一步建议先验证第一步，不需要你现在替我们选择技术实现方法。
